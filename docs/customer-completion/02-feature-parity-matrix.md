# 02 — Customer feature parity matrix

Trạng thái thể hiện implementation hiện tại sau audit/sửa lỗi. “Chưa có E2E” là giới hạn kiểm chứng môi trường, không phải khẳng định API hỏng.

### Kết luận parity

Customer routes cốt lõi đã có màn hình và API path tương ứng. Các gap có thể sửa trong Mobile đã được xử lý cho envelope, review history, notification preferences, avatar upload, cancellation preview, wallet withdrawal, profile gender/DOB và discovery filters/sort. Các phần còn Partial/Blocked: Google callback, address/session-management APIs, date availability (Web defect + thiếu aggregate API), hai style label không có code Backend, external notification/chat config và chưa có staging E2E.
